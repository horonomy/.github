# Host adapter v1 vectors

These vectors are authored, sanitized contract examples. They are synthetic and are **not** captured from a running Claude Code, Codex, or external adapter process. Claude and synthetic-external examples were authored from this contract's shape only. The Codex provider/version/native event label are candidate identifiers based on the [Codex hooks documentation](https://developers.openai.com/codex/hooks) and source tag `a956835d020762cb2b570053af06f643a11c0ecc` (Codex 0.160.0). These fixtures do not prove that a candidate event payload or any capability works. Identity fields follow `governance/product/execution-identity-contract.md` v1. No credentials, native payloads, or user paths are included.

Files prefixed `valid-` must validate against the named schema. `valid-event-record-only.json` demonstrates an observation whose action facts are absent; it carries no action coverage and a product binding must report coverage unavailable. Files prefixed `invalid-` are regression vectors that must be rejected. Semantic tests also mutate valid examples to cover identity-v1 lineage parity, fact completeness, response branch exclusivity, operation typing, unknown providers/extensions, future version incompatibility, schema-profile rejection, and configuration value validation. The trust-drift vector deliberately has unequal trusted/current digests and is consumed by a semantic assertion: JSON Schema cannot establish filesystem identity or freshness. A schema-valid synthetic vector proves only contract shape.

The separate isolated native Codex audit/probe observed allow, deny and rewrite vectors, malformed/timeout fail-open behavior, and an untrusted hook being skipped. It did not validate real PermissionRequest, subagent, asynchronous, administrator-disabled-hook, or sandbox behavior, nor universal enforcement.
